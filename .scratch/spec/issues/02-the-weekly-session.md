## Question

What does the one weekly session actually look like, step by step, on a phone and on a
laptop?

This is the product. The household interacts with the tool **once a week**, and everything
happens in that sitting. The old repo fixed the order and it is settled: feedback first,
then the week, then adjustment, then the list.

What is not settled is the screen. Build a clickable prototype and react to it.

Specific questions the prototype must answer:

1. **Feedback.** The briefing names last week's meals with no recorded outcome. How many
   prompts is too many? What does a household do when it genuinely cannot remember?
2. **The week as a pool** (decision 15). Five meals, each with a reason, an effort pair, a
   yield, and a leftover marker. How does the effort mix get shown so *"three of five are
   low-active, so any night can be a bad night"* reads at a glance?
3. **Adjustment.** Swap, lock, reshuffle, change servings, add guests, change the number of
   nights. Which of these are one gesture and which need a screen? Note that swap is one
   decision, not a drop plus a refill.
4. **Regeneration fills holes, never re-rolls the week.** What does that look like?
5. **The list.** By aisle, with provenance on every line, what is shared between meals, what
   is stranded if a night falls through, and the likely-owned flags. This screen gets read
   in an aisle on a phone.
6. **Where do the three model jobs surface?** Planning, *Find something new*, and pasting a
   recipe link.
